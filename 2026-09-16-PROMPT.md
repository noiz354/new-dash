## Prasyarat environment (lakukan sekali sebelum TASK 1)

- `npm install`, lalu `npm run db:setup`. PENTING: database lokal PGlite single-writer — hentikan dev server sebelum `db:setup`, lalu start ulang.
- Jalankan dev server di port unik (jangan pakai port yang sudah terisi), contoh `npm run dev -- -p 3145`.
- Login runtime memakai akun seed + MFA dengan pola TOTP dev-hint — tiru pola login di `tests/integration.test.ts`, jangan hardcode kredensial di luar pola itu.
- Kerja di branch `arena/01a0a835-new-dash`; satu task = satu commit + push; jangan commit file generated (`next-env.d.ts`) dan jangan sentuh arsip `page-layout-specs/` bila muncul sebagai untracked.

## 0. Konteks repo (wajib dibaca dulu)

- Repo: Next.js + Drizzle (PGlite) + PWA, branch kerja `arena/01a0a835-new-dash`.
- Sumber kebenaran status: `docs/audit-non-e2e-remediation-map.md` (seksi F2, F12, F23, F25, F15, F26, F27) dan `docs/audit-full-app-truth-map.md`.
- Aturan repo: `AGENTS.md` — yang terpenting: **jangan edit** `stitch_facility_maintenance_platform_ui/`; ID operasional monospace; klaim visual wajib diverifikasi lawan mockup.
- Pola backend yang berlaku di repo ini (tirukan dari route/service yang sudah ada, mis. `app/api/findings/route.ts`, `lib/services/inspection-service.ts`): setiap route memakai pembungkus `withRoute` dengan nama operasi dan izin; body divalidasi zod; mutasi menulis baris audit dalam transaksi yang sama; mutasi berisiko double-submit memakai kunci idempotensi; nomor dokumen canon (`WO-`, `FND-`, `GRN-`, dst.) memakai sequence server, tidak pernah dibuat acak di klien.
- Pola izin: tambah izin baru di berkas RBAC mengikuti penamaan bertitik yang sudah ada, lalu petakan ke peran yang tepat.
- Migrasi database: berkas SQL bernomor di `db/migrations/` (contoh terakhir `0004_pink_gargoyle.sql`); seed idempoten di `db/seed.ts`.
- Test: `tests/integration.test.ts` (test perilaku API/service) dan `tests/audit-truthfulness.test.ts` (test penjaga: teks fiksi dilarang muncul). Keduanya wajib hijau: `npm test`. Wajib bersih juga: `npx tsc --noEmit`.
- Runtime: jalankan dev di port unik, login sebagai seed user, verifikasi lewat browser + panggil API langsung (kasus negatif 4xx/409 wajib dicoba, bukan hanya happy path). Konsol browser harus nol error JS (artefak probe negatif yang disengaja didokumentasikan, bukan diabaikan).
- Setiap task selesai = update kedua peta audit (tandai `CLOSED`), update `TODO.md` + `PROGRESS.md`, **satu commit per task** lalu push. Verifikasi isi commit sebelum klaim (pernah terjadi klaim hapus file padahal file masih ada).
